# Vision detection dashboard

The React dashboard connects to `vision_server.py`, which runs the existing MindVision detection loop and optional PLC output. One process owns the camera. Stop any existing `python main.py --camera ...` session and close the vendor camera application before starting inspection here.

## Build once

Install Node.js 22 and pnpm 10.34.3 (also specified in `.mise.toml`). From the repository root:

```powershell
cd UI
pnpm install --frozen-lockfile
pnpm build
cd ..
```

The backend uses the existing Python dependencies (`opencv-python` and `numpy`), plus the Python standard library. Camera operation requires the installed MindVision SDK/driver and a matching `RefPic/Ref1.png`.

## Run

From the repository root, with optional PLC output enabled:

```powershell
python vision_server.py --plc-config plc_config.json
```

For camera inspection without PLC communication:

```powershell
python vision_server.py
```

Open **http://127.0.0.1:8765**, then click **Start inspection**. The service does not open the camera or connect to the PLC before that command. It binds to the local computer only. Press Ctrl+C in the terminal to shut down.

Camera options are supported, for example:

```powershell
python vision_server.py --camera-index 0 --sdk-dir "C:\path\to\SDK\x64" --frame-rate 10 --confirm-frames 3 --plc-config plc_config.json
```

Use `python vision_server.py --help` for all options. Settings shown under Configuration are read-only; configure them at launch and detector parameters in `Detection.py`.

The camera adapter automatically looks for the SDK under the standard MindVision installation in Program Files. For a custom installation, use `--sdk-dir` pointing to the folder containing `MVCAMSDK_X64.dll` for 64-bit Python. After updating Python source files, stop the running service with Ctrl+C and restart it to load the changes.

## Operator behavior

- The preview displays actual raw or annotated camera pixels. Preview delivery is limited to a maximum width of 1280 pixels; Take photo downloads that JPEG preview. Alarm evidence retains the full-resolution PNGs generated by the existing detector.
- Frames processed and FPS refer to inspection frames, not production units. Frame count covers the current server session, including restarts of inspection within that session.
- Stop inspection stops camera processing and PLC vision-health updates. It does not reset the software alarm latch. Restarting inspection within the same service preserves the latch; restarting the Python service initializes its software state, as the CLI does. PLC ladder remains responsible for its own latch.
- Reset requires consecutive clear frames. When PLC output is enabled, the existing PLC connection, recent-inspection and configured reset-coil checks also apply. A successful response means the software latch was cleared and the PLC reset request was queued; it does not confirm a physical output changed.
- Faults and frames older than five seconds are unavailable, never a clear inspection result. Camera, processing and evidence-storage errors stop inspection.
- Detections lists up to the latest 100 alarm evidence sets from `Results/`, including evidence created before the service started. Timestamps in existing filenames are local recording times. Raw/annotated/mask links open available saved PNGs.

## Frontend development

Keep the backend running at its default port 8765. From `UI/`, run `pnpm dev` only if a development server is not already running. Open http://localhost:8443. Vite proxies `/api` to the backend. Rebuild with `pnpm build` to update the dashboard served by Python.

```powershell
pnpm typecheck
pnpm build
```

Backend regression checks, from the repository root:

```powershell
python -m unittest discover -s tests -v
```

Hardware acceptance: start inspection with the real reference/camera, confirm the raw and annotated previews, introduce a test object to confirm an alarm/evidence set, remove it and verify reset eligibility, then verify PLC ladder/output behavior separately. Camera and PLC tests should be performed under the operator's normal controlled test procedure.
